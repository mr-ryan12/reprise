# React Router Expert

Reprise uses **React Router v7 in framework mode** with Vite. Routes are declared
explicitly in `app/routes.ts` (not filesystem-magic) and implemented in
`app/routes/`. **Always import from `"react-router"`** — never `@remix-run/node`
or `@remix-run/react`.

## Typed route modules

Each route gets generated types. Import them and use the `Route.*` arg types:

```ts
import type { Route } from "./+types/shows";

export async function loader({ request }: Route.LoaderArgs) { /* ... */ }
export async function action({ request, params }: Route.ActionArgs) { /* ... */ }
export function meta({ matches }: Route.MetaArgs) { /* ... */ }
```

Types are generated by `react-router typegen` — `yarn typecheck` runs it before
`tsc`. If `./+types/<name>` can't resolve, run `yarn typecheck` to regenerate.

## Returning data

Loaders and actions **return plain objects**. This project does not use `json()`
or the `data()` helper:

```ts
return { shows, totalPages, currentPage, query };
```

To signal an error or non-200, **throw a `Response`** — it's caught by the route's
`ErrorBoundary`:

```ts
throw new Response("Failed to load shows", { status: 500 });
```

## Auth

`requireAuth(request)` returns the `userId` and throws a redirect to
`/login?redirectTo=…` if unauthenticated. Call it at the **top** of protected
loaders/actions. Public pages (browse, search, detail) use `getOptionalUser`,
which returns `userId | null`. Both live in `~/utils/auth.server`.

```ts
const userId = await requireAuth(request);      // protected
const userId = await getOptionalUser(request);  // public, may be null
```

## Error handling — wrap every async op

Every `await` that can fail goes inside `try/catch`; the catch logs with context
and throws a `Response`.

**Loader:**
```ts
export async function loader({ request }: Route.LoaderArgs) {
  try {
    const result = await getShows(page);
    return { ...result };
  } catch (error) {
    console.error("Failed to load shows:", error);
    throw new Response("Failed to load shows", { status: 500 });
  }
}
```

**Action** (intent-discriminated, validate → throw `Response`; re-throw redirects
and validation Responses so they aren't swallowed by the catch):
```ts
export async function action({ request }: Route.ActionArgs) {
  try {
    const userId = await requireAuth(request);
    const formData = await request.formData();
    const intent = String(formData.get("intent") ?? "");

    if (intent === "unfavorite-show") {
      const showId = String(formData.get("showId") ?? "");
      if (!showId) throw new Response("Show ID required", { status: 400 });
      await toggleFavorite(userId, showId);
      return { ok: true };
    }

    throw new Response("Unknown intent", { status: 400 });
  } catch (error) {
    if (error instanceof Response) throw error; // redirects + validation
    console.error("Failed to update favorite:", error);
    throw new Response("Failed to update favorite", { status: 500 });
  }
}
```

## Reading data + mutations in components

```ts
const data = useLoaderData<typeof loader>(); // full type inference, never cast
```

- **Inline mutations** (favorite toggle, per-row actions): `useFetcher` with a
  hidden `intent` field.
- **Search / navigation-affecting submits**: `<Form method="get">` +
  `useSubmit` (see the debounced search in `app/routes/shows.tsx`).
- Navigate with `<Link>` / `useNavigate` / `useSubmit`. Never touch
  `window.location` for client navigation.

## Error boundaries

Export an `ErrorBoundary` that narrows with `isRouteErrorResponse`:

```ts
export function ErrorBoundary() {
  const error = useRouteError();
  const message = isRouteErrorResponse(error)
    ? error.data || "Something went wrong."
    : "An unexpected error occurred.";
  // ...render
}
```

## Adding a route

Register it in `app/routes.ts` (`index`, `route(path, file)`) — creating the file
in `app/routes/` alone does nothing. Server-only helpers use the `.server.ts`
suffix; DB/business logic goes in `app/services/`, not the route.
